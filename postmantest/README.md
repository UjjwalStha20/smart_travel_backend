# Postman API Test Suite — Nepal Travel Planner backend

Hand-authored Postman suite (generated by `/tmp/opencode/gen_postman.py`) produced from a full
audit of the FastAPI source in this repo. Every test's expected status code, payload, and
response shape mirrors the *actual implementation* in `app/routers/*.py` and `app/schemas/*`.

## What's here

| File / folder | Purpose |
|---|---|
| `Nepal-Travel-Planner.postman_collection.json` | Postman collection, 18 folders, **369 requests** over **185 endpoint paths** |
| `Nepal-Travel-Planner.postman_environment.json` | Postman environment (tokens/IDs captured automatically at runtime) |
| `collection.json` / `environment.json` | Plain JSON indexes of the above (machine-readable) |
| `TEST_CASES.md` | Every test case: ID, method, endpoint, auth, expected status |
| `modules/` | One JSON file per test case: `<ID>.json` describing its request + assertions |
| `sample-files/` | `sample.png` (blank 1x1) and `sample.txt` used by multipart-upload tests |

## Prerequisites (before running)

1. PostgreSQL running and `DATABASE_URL` reachable from `.env`.
2. Seed data loaded once: `python scripts/seed.py`.
3. Ollama with `qwen3:8b` loaded for LLM features (chat, trip-plan messages, AI-generated
   destination content, recommendations).
4. Internet access for `/travel/*` (weather, flights, maps) and directions endpoints.

## Import & run

1. Postman → *Import* → `Nepal-Travel-Planner.postman_collection.json` and
   `Nepal-Travel-Planner.postman_environment.json`.
2. Select the **Nepal Travel Planner** environment.
3. Set `base_url` to `http://localhost:8000` (or the deployed base URL).
4. **Run folders in order.** The suite is stateful: folders create resources that later
   folders read/update/delete. The required order is the collection's folder order
   (01 Setup & Health … 18 Admin Dashboard).
5. Recommended: Postman runner on the whole collection, or run folder-by-folder.

Postman's `pm.environment.set()` persists tokens and record IDs across requests, so the
variables below are maintained automatically:

| Variable | Set by | Notes |
|---|---|---|
| `uniq`, `reg_email`, … | first request (SETUP-001) | `uniq = Date.now()/1000` |
| `traveler_token` / `admin_token` / `second_user_token` | AUTH-001/002/003 | seeded-user logins |
| `user_id` | AUTH-015 | `GET /auth/me` |
| `destination_id`, `address_id`, `attraction_id`, `route_id`, `accommodation_id` | SETUP-002…006 | seeded rows |
| `new_destination_id` | DEST-014 | test destination, deleted in 05 Destination Content |
| `created_user_id`, `created_user_email` | USER-005 | admin-created user, deleted in 03 Users |
| `trip_id`, `trip_b_id`, `user_trip_id`, `user_trip_del_id`, `itinerary_id`, `review_id`, `saved_id`, `photo_id`, `blog_id`, `blog_slug`, `conversation_id`, `reset_token`, `entry_fee_id`, … | created by the tests that use them | |
| `invalid_token` | pre-set | `Bearer deadbeef…` |

For the login and register tests we intentionally **log in as the seeded accounts**
(`admin@example.com`/`admin123`, `anusha@admin.com`/`admin123`, `john@example.com`/`password123`,
`ujjwal@gmail.com`/`password123`) instead of creating fresh accounts, because both endpoints
are rate-limited (see below).

## Rate limits (why some tests accept 429)

The backend applies `slowapi` limits:

- `POST /auth/register` — 3 requests/min
- `POST /auth/login` — 10 requests/min
- `POST /chat/` — 10 requests/min
- Global — 60 requests/min

Negative tests that could trip these limits (e.g. duplicate-register, unknown-user login,
unknown-destination chat) therefore assert `422` **or** `429` (transient). If a run shows a
sprinkling of `429`s on those exact cases, it is *expected*, not a failure. The happy-path
register and login calls are kept under the limits per run.

## Multipart / file-upload tests

These requests send `multipart/form-data` with a file attachment. In Postman the file input
`src` is pre-pointed at `sample-files/` under this folder, but you must re-browse/set a
real file path on your machine (or fill it at runtime):

- `DEST-014` (create destination admin,+PNG) — expect **201**
- `DEST-017` (create as traveler → 403), `DEST-018a/e` (bad extension / no file → 400) — file not strictly needed
- `PHOTO-004` (upload valid PNG — expect 201), `PHOTO-005` (valid TXT — reusing sample.txt → 201),
  `PHOTO-005b` (bad extension → 400)

## LLM-dependent tests

Tests that depend on Ollama (chat messages TRIP-*/CHAT-*, `POST …/content/regenerate`,
`POST …/things-to-do`, `POST …/highlights`, `POST …/faqs`, destination content auto-generation)
will fail with a 500 if Ollama is not running (`qwen3:8b`). They are marked in the
`note` field of the module JSONs. Running with Ollama gives full coverage.

## Known backend behavior reflected in this suite

These are real properties of the current API (not test bugs). See `FINAL_REPORT.md`.

- `GET /users/`, `GET /users/{id}`, `GET /user-trips/`, `GET /user-trips/{id}`,
  `GET /activity-logs/` are **public** in this build (no auth required) — the suite
  therefore calls them without a token and expects 200.
- `POST /users/` returns **200** (not 201).
- The photo router is registered with a non-standard dependency style (`param: X = None`),
  so its injection behavior differs from other routers.
- `POST /auth/register` performs no meaningful validation, so register tests tolerate both
  201 (“invalid” payloads) and 422 without asserting either.
- `POST /optimization/route` with an empty body crashes the route resolver and returns a
  500 rather than a 422 — the empty-body case (OPT-014) documents this explicitly.
- AI destination content is generated/lazy-stored via Ollama and may 500 without it.

## Interpreting results

- `pm.expect(json.items).to.not.be.undefined` style assertions are wrapped in
  `if (pm.response.code === X)` so a wrong status fails loudly but downstream shape-checks
  don't produce cascading noise.
- Some requests save an ID only when the response matches the expected code; a failed
  upstream request therefore does not poison later tests (they fail on the status check
  instead of on undefined references).
